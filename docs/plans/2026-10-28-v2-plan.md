# PokéDex Manager v2 — plan

Branch `v2` (from `main` @ `9de1afb`). `main` / `v1.0.0` stay as the delivered version.
Mode: agentic, TDD, one Conventional Commit per logical change.

## Phase 1 — Backend foundation (testable app)

Goal: every external dependency (Mongo, PokéAPI, clock) is injected, so tests run with fakes.

1. **Test harness.** Add `pytest`, `pytest-asyncio`, `ruff` as dev deps. Tests use a real Mongo
   test database (`pokedex_test`, dropped per test) and `httpx.MockTransport` as a fake PokéAPI.
   Characterization tests for the current endpoints first (auth + pokemon), so the refactor is safe.
2. **App factory + composition root.** `create_app(settings)`; the lifespan creates the Mongo
   client, one shared `httpx.AsyncClient` (timeout, connection pooling) and the services, and
   stores them in `app.state`. Routers get them through `Depends` — no module-level singletons.
3. **PokéAPI adapter.** `PokeAPIClient` class (Adapter pattern: speaks PokéAPI, returns plain data,
   raises domain errors) replacing the `_request` / `_task` pairs.
4. **TTL cache.** Small in-memory `TTLCache` with an injectable clock (detail, list, type, name index).
   Biggest win: the type filter no longer downloads the full type list on every page.

## Phase 2 — Backend features

5. **Partial search / autocomplete.** `GET /api/pokemon/suggest?q=pika&limit=8` →
   `[{id, name}]`: prefix matches first, then substring; uses the cached name index
   (one PokéAPI call per TTL).
6. **Favorites (personal collection).** Collection `favorites {user_id, pokemon_id, name, created_at}`,
   unique index `(user_id, pokemon_id)`.
   `GET /api/me/favorites`, `PUT /api/me/favorites/{pokemon_id}` (idempotent, 404 if the Pokémon
   does not exist), `DELETE /api/me/favorites/{pokemon_id}` (idempotent, 204).
7. **Login rate limit.** Sliding window in memory: 5 failed attempts per email and 20 per IP per
   minute → `429` with `Retry-After`. Injectable clock. (Single process; Redis would be the
   multi-instance version — documented.)
8. **Smaller detail response.** `response_model` with only the fields the UI uses
   (+ cry URL, official artwork, shiny sprite).

## Phase 3 — Frontend QoL and motion

9. **Frontend tests.** Vitest + Testing Library; e2e specs with Playwright (written, run at the end).
10. **Better search.** Autocomplete combobox (debounced, ARIA combobox, ↑/↓/Enter/Esc), `/` shortcut.
11. **Favorites UI.** Heart toggle on cards and modal, "Mi colección" filter.
12. **URL state.** Page, type, search and open Pokémon in the query string; back closes the modal.
13. **Detail "holo card".** Pointer/gyro tilt + holographic sheen colored by type, stat bars,
    cry button, prev/next. Static under `prefers-reduced-motion`.
14. **Transitions.** View Transitions card → modal (fallback: none), skeleton loaders, staggered grid.
    Animation source: the user's "animaster" (ask in the other profile) or GSAP with
    `gsap.matchMedia` honoring reduced motion (BifrostCode `use-motion-effect.ts` pattern).

## Phase 4 — Delivery

15. CI (GitHub Actions: ruff + pytest with a Mongo service, eslint + vitest + build).
16. README v2 section, screenshots, Postman collection, deploy `v2` to its own subdomain.

## Verification per task
Backend: `uv run pytest -q` + `uv run ruff check`. Frontend: `npm run lint` + `npx vitest run` + `npm run build`.
UI: screenshots at 320 / 768 / 1280 / 2560. E2E: only at the end of Phase 3.
